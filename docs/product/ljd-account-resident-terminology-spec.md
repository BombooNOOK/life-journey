# Life Journey Diary｜アカウント・森の住民 用語基準

**Status:** Current Product Terminology / Source of Truth

## 製品の前提

Life Journey Diary（LJD）は、**1アカウント＝本人1人の人生記録**を基本とする。

家族・友人・旅行・飲食店等の思い出は、別の人物枠に日記を分けず、本人の「あしあと」として保存し、タグ等で整理する。

## 用語定義

### アカウント

ログイン・メールアドレス・認証・サービス利用主体・全データの所有単位。

**使う場面:** 法務文書、認証エラー、技術説明、内部コード。一般向けメニュー名としては「住民登録情報」を優先する。

### 住民登録情報

一般UIにおける登録内容・契約・セキュリティ確認画面の表示名（ページ `/orders/account`）。

内部的にはアカウント設定を指すが、ユーザー向けには住民登録の確認として案内する。

### 森の住民

LJD を利用している本人を、BambooNOOK の森の中で表す呼称。

### 住民登録

本人が初めて BambooNOOK の森へ入る際の登録体験の名称。

例: はじめての住民登録、森の住民登録。

### 森の住民票

`AccountSettings` にある住民番号・森でのおなまえ等を表示する、本人のカード。アカウント共通。

おなまえ変更は住民票側。将来の顔アイコン変更も住民票ページに接続する。

### あしあとのバックアップ

あしあと本文・写真等の ZIP 書き出し機能の一般向け名称。

現状のバックアップ対象はあしあと系のみ。森ログ・アルバム・映写便り等は含まないため、「記録のバックアップ」等の過大な名称は使わない。

（将来案）ハイブリッド化時の端末移行／復元を含む「森のお引越し」は別機能として検討する。バックアップ範囲自体の拡張はここでは行わない。

「データ管理」という曖昧な一般UI名称は使わない（役割の重複回避）。

### 森に入る（ログイン）／森から出る（ログアウト）

一般向け主要UIの入退室表現。括弧内で意味を補足する。

法務、認証エラー、APIメッセージ、aria-label 等では必要に応じて「ログイン／ログアウト」を維持する。

### Profile（内部実装）

内部のデータパーティション（`profile` / `profileId` 等）。

**ユーザー向け概念としては使用しない。**

新規利用者には Default Profile を1件自動確保し、存在を意識させない。管理者のみ既存複数 Profile への切替互換を当面残す（新規作成はしない）。表示は「既存の記録枠を切り替える」。

## 住民登録をやめる（アカウント削除）

一般向け主要表示名。世界観表現に括弧で「アカウント削除」を併記する。

確認画面では、実際にログイン用アカウントと関連データが削除されることを明確に説明する。婉曲だけで重大性を薄めない。

削除処理（`deleteUserAccount`）自体は変更しない。
